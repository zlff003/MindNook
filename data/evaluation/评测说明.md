# RAG 评测说明

## 评测目标

这套评测用于发现 ContextAgent 的 RAG 路由、召回、融合、重排和上下文扩展是否发生回归。它不用于证明系统具备临床效果，也不能代替心理专业人员审核。

## 数据组成

`RAG评测集.jsonl` 当前包含 100 条中文样例：

- 85 条需要检索的心理支持、安全风险或隐私伦理 Query；
- 15 条不应触发 RAG 的普通问答负样例，其中包含关键词重叠、引用风险台词等困难负例；
- 检索样例覆盖学业、睡眠、焦虑、低落、人际、家庭、校园适应、安全风险和隐私伦理；
- 其中 10 条为安全关键样例，9 条标注了跨 Chunk 证据短语；
- 新增样例覆盖口语、隐式表达、同义改写、错别字、噪声输入、长叙述、混合意图、功能受损、第三人称危机和服务边界等情况。

每行是一个 JSON 对象：

| 字段 | 含义 |
|---|---|
| `id` | 稳定且唯一的样例编号 |
| `query` | 用户输入 |
| `category` | 人工标注主题 |
| `relevant_sources` | 期望命中的知识文件名，可有多个 |
| `expect_rag` | ContextAgent 是否应触发 RAG |
| `evaluate_retrieval` | 是否参与检索排名指标 |
| `safety_critical` | 是否属于安全关键样例 |
| `challenge_tags` | 可选的挑战类型标签，用于分层观察真实表达上的表现 |
| `evidence_phrases` | 可选的人工证据短语，用于检查第一名原始 Chunk 或扩展上下文是否包含关键证据 |

## 自动指标

评测会分别输出仅向量、仅 BM25、归一化融合、本地重排和最终上下文五个阶段的 Hit@1、Recall@3、MRR@3、nDCG@3 与 Top1 证据召回。报告还会输出相邻阶段的指标增量、来源排序胜/平/负、证据胜/平/负，以及挑战类型分层结果。最终验收还检查：

- 总体 Hit@1 不低于 0.85；
- 总体 Recall@3 不低于 0.95；
- 普通问题的 RAG 误触发率不高于 0.02；
- 安全知识 Hit@1 与 Recall@3 均为 1.0；
- 返回上下文重复率不高于 0.15；
- 开启回复质量评测时，输出边界、联系方式真实性和高风险现实行动通过率均为 1.0。

## 运行方式

```bash
python -m app.rag.evaluation
python -m app.rag.evaluation --strict
python -m app.rag.evaluation --evaluate-answers --strict
```

命令会更新 `RAG评测报告.json` 和 `RAG评测报告.md`。`--strict` 适合接入 CI，未达到硬阈值时返回非零状态。

## 人工评审

真实模型的回答需要使用 `回答质量人工评审表.md` 盲审。自动词面重合只能用来发现明显回归，不能判断同理心、建议是否合适或心理安全性。

## 维护规则

- 线上或测试中发现真实失败表达时，应先加入评测集，再修复检索；
- 相关来源由至少一名知识维护者复核，安全样例还需心理专业人员复核；
- 不要为了提高分数删除困难样例或降低安全硬阈值；
- 知识文件改名时同步更新 `relevant_sources`；
- 当前 100 条数据仍属于回归集；进一步调参前应将样例划分为开发集和不参与调参的保留测试集，避免过拟合；
- 不得为了证明某个检索阶段有效而挑选样例；阶段是否有效应由增量、胜负数和保留测试集共同判断；
- `evidence_phrases` 必须逐字存在于至少一个 `relevant_sources` 文件，并优先选择需要相邻 Chunk 才能完整覆盖的证据组合。
