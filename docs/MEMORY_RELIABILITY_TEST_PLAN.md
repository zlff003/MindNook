# 长对话记忆可靠性修复测试方案

制定时间：2026-10-19。本文先于本轮测试执行保存。

## 测试边界

原始聊天记录仍为依据。新增事实必须有对应消息的完整句子原文；模型不再重写摘要或在提取时更新/撤回事实。
更正经过独立审核，事务按目标事实记录事件。摘要是事实投影，失败不能推进提取进度。
默认前台不等待记忆模型，后台提取、更正、压缩；原文召回补足遗漏，并携带后续更正。

所有测试使用隔离 SQLite、测试缓存及独立向量集合；不修改业务数据库。不把 Mock 通过当作语义效果通过。

## 执行次序与判定

1. 静态检查：编译变更模块及脚本，检查 diff 中空白错误。
2. 更新原有 memory 回归到新契约，保留边界、隔离、事务、索引、租约、预算等原有保障。
3. `tests/test_memory_reliability.py` 验证以下具体故障。
4. 全量 pytest，确认聊天、Harness、后台任务和 API 兼容。
5. 使用真实配置的大模型 API 再跑同一 60 轮素材，另加后台任务执行，独立目录、明确调用上限。
   记录模型输入输出、请求数、完成/失败原因、边界、事实、事件以及最终回答。
   分别判断「存进去了」「召回出来了」「回答对了」，不能用脚本 completed 代替语义成功。

|编号|具体输入/注入|检查|
|---|---|---|
|R01|第一句为考试担忧、凌晨两点；当前输入为问助教|提取请求无当前 focus；引用旧消息的助教事实被拒绝|
|R02|模型提取输出 retract/update 或旧 summary_items 契约|拒绝写入，边界不动|
|R03|原句「我没试过清单」却引用「试过清单」|不能截掉否定；引用必须是完整句子|
|R04|同一句两个独立事实；更正清单归属并确认散步|只修改清单，散步仍有效，新更正证据仍可提取|
|R05|模型错误提议撤回散步，独立审核否决|无撤回事件/索引变更，待核对证据保留|
|R06|只处理部分消息或模型输出截断|整批拒绝，已花费 usage 仍记录|
|R07|摘要容不下旧事实，再换话题|旧事实仍在 SQL，摘要不再因覆盖校验停滞|
|R08|摘要边界超过提取边界|提取从自己的游标继续，不能跳过遗漏消息|
|R09|超时、立即下一轮、后台重试|前台不反复调用；后台可缩小失败批次；失败不推进游标|
|R10|更正后又发普通聊天|原更正任务继续执行；更早更正不能覆盖新版本|
|R11|新会话问最早几点睡；事实未成功抽取|从原消息找回两点；必须带后续相关更正，不能回流作废事实|
|R12|另一个用户有同主题/独有词|SQL 与原文召回均不能泄露对方内容|
|R13|无相关向量命中但有稳定沟通偏好|小预算独立注入，不能撑爆总上下文预算|
|R14|旧版无 quote 的记忆/旧摘要|迁移存档并停止当成已核验事实；原消息保留、重建任务可重复迁移|
|R15|默认前台与实际后台 dispatcher|前台零记忆模型调用，后台仍能完成事实写入、索引同步|
|R16|索引异常、事务 outbox 异常、并发 CAS|正文和事件保持事务一致；索引可重试，不误报处理成功|

首轮真实 API 后补充（在第二轮执行前确定）：更正模型只选择目标，不再生成证据字段；
独立审核只批准清单、否决散步时，清单可更新，散步不变，批次必须标 partial；
“最初”查询加入大量更高词频的后续睡眠记录，仍优先原始首条；
新增真实 ThreadedToolDispatcher 及影子数据库准备测试。

## 真实 API 问答判定

- 最初为什么失眠、大约几点入睡：考试担忧、凌晨两点。
- 呼吸练习是否做过：仅建议/考虑，没有实施证据。
- 清单效果归谁：更正后为同学，用户自己没试过。
- 散步归谁、效果怎样：用户自己，身体放松而担心未完全消失。
- 换话题是否表示问题已解决：不能推断解决。
- 跨会话原始事实和更正仍可访问；跨用户不泄漏。
- 摘要边界推进、待处理批次和更正均单独列出；若未处理完，诚实列为未通过/待确认。

## 限制

原文引用能防错配和改写，不能证明模型的分类或归属判断永不出错。独立审核仍可能犯错。
原文回退采用有上限的词项搜索，可能漏掉同义表达和候选窗口中间的记录；检索失败不得说用户没说过。
长消息不能完整放入预算时保留原记录并报告未完成，不截去否定后当成完整事实。
