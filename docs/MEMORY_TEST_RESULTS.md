# Memory 升级测试结果

日期：2026-10-14。依据：[测试前制定的方案](./MEMORY_TEST_PLAN.md)。实现说明：[MEMORY.md](./MEMORY.md)。

## 代码变更

- 新增持久化会话摘要与学生长期记忆，结构化保存来源、证据阶段、有效状态、版本和索引同步版本。
- 近期窗口改为按 SQL 摘要边界增量加载；Redis 40 条仅为缓存上限，压缩后默认保留 8 条，两次压缩之间原文可继续增长。
- 摘要和长期记忆候选同次生成，来源校验后与处理边界、索引任务原子提交；失败不推进边界。
- 实现独立 Chroma 记忆集合、学生过滤、SQL 当前正文回查、覆盖去重、短会话提取与跨会话召回。
- 实现更正/效果演变、失败暂时停用、跨会话旧摘要失效、后台版本保护、会话租约与持久化重试。
- 为所有 Runtime/摘要调用增加保守预算检查和输出上限，保留流式真实 usage；记忆模型用量写入 `MEMORY_CALL`，Trace 保存实际使用的记忆快照。
- 更新旧库兼容迁移、环境变量示例和说明文档；原升级方案保留为设计基线。

- 临时 SQLite、内存 Redis 替身、脚本化/Mock 模型；hash embedding，关闭生产 reranker。
- 实际执行 Chroma EphemeralClient 的插入、学生过滤、更新和删除；HTTP/SSE 协议使用 MockTransport。
- 没有调用真实模型，没有修改 `.env` 或业务数据库。

## 关键断言

- 用确定性的预算和消息 ID 验证 20/32 条两次压缩边界，19 条历史不提前压缩。
- 2200 条历史分批收敛，已处理来源 ID 与最后保留原文拼接后等于完整原始序列，既不重复也不遗漏。
- 模型超时、非法 JSON、伪造来源、摘要超长、事务中途失败均不推进边界。
- 验证同来源两个事实均被保留、相同操作重放幂等、旧版本提交拒绝。
- 验证明确更正、时间演变、失败停用、指代歧义、旧会话重新打开和被停用摘要的后续压缩。
- 验证短会话跨会话提取、同会话历史召回、两次学生身份检查、完整/部分覆盖去重、向量滞后和索引故障恢复。
- 验证两个并发 worker 只有一个能领取同一任务、有效租约不被启动恢复抢走、过期聊天持有者不能提交。
- 验证模型调用前预算拒绝、输出 Token 上限、SSE usage 的实际输入/输出用量、旧库迁移重复执行不破坏数据。

## 发现与修复

1. **短会话提取完成后持有 SQLite 写锁**：`ensure_summary()` 对已存在记录仍执行插入忽略，空批次返回未结束事务。改为先读取已有摘要，并在空批次路径明确结束事务；索引 worker 随后可独立领取任务。
2. **同来源多事实丢失风险**：只按类型和来源去重会合并同一消息的不同事实。去重键纳入规范化内容，并新增“同源不同事实 + 重放”的双重断言。
3. **旧事实变换类型后复活风险**：写入时核对所有失效证据，并同步停用引用这些证据的旧摘要。
4. **被停用摘要阻塞后续压缩风险**：保留 SQL 审计记录，但不把停用条目作为普通摘要更新的有效输入。

前三类 Memory 结构化输出的语义由脚本化模型/Mock 提供；测试证明写入、状态变化和注入规则，不证明真实模型永远作出正确语义判断。

## 警告与未验证范围

- 测试产生既有依赖的弃用警告（Chroma/Pydantic、Starlette multipart、pytest-asyncio）；Chroma 工程验证另有 telemetry API 兼容警告，未影响索引操作与检查结果。
- 本次未执行真实模型盲审、真实 FastEmbed 召回率测试、在线 Redis 故障恢复或 MySQL 并发测试，不能用离线结果替代。
- 预算使用 UTF-8 字节保守估算，不是模型专用 tokenizer；精确成本以服务端 usage 为准。服务端未返回费用信息的失败调用只能记录失败，无法恢复实际计费。
- 单条历史消息超过单批处理预算时保持边界并降级；大规模索引重建与真实部署容量评估仍需专门运行环境。

复现时使用测试方案中的命令，加 `-p no:cacheprovider -o addopts= -q` 可得到与本次相同的明确通过数量输出。日志目录为本地忽略文件，结果摘要保存在本文件。
