# Memory 升级测试方案

日期：2026-10-14。状态：测试执行前制定；执行结果另记 `MEMORY_TEST_RESULTS.md`。

## 目标与范围

验证最近原文、持久化摘要、学生长期记忆的完整读写闭环，重点验证消息不遗漏、失败不推进边界、来源可信、身份隔离、用户更正优先、预算可控及重复任务幂等。

本方案在首次测试命令之前落盘。先完成实现，再按本方案编写和运行测试；发现缺陷后修复并重复相关测试，最后执行回归。

## 隔离与证据

- 单元/集成测试用 TemporaryDirectory 内 SQLite，InMemoryRedisStore，确定性模型或脚本化模型响应。
- 使用明确的 `_env_file=None`、`MODEL_PROVIDER=mock`、hash embedding 与本地 reranker，禁止请求线上模型、读写业务数据库和业务 Chroma 数据。
- 向量集成测试实际使用 Chroma EphemeralClient + hash embedding，集合使用独立命名空间；不可只依赖向量 mock 宣称完成集成验证。
- 协议测试用 httpx.MockTransport 返回确定性响应与流式 usage，不需要网络。
- 核心断言以 SQL 结果、处理边界、来源消息 ID、实际传入模型的 messages、任务状态为依据，不仅检查“函数没抛异常”。
- 每个用例创建独立数据；失败注入覆盖模型、事务、索引、Redis、过期版本等边界。测试中不使用真实账号密钥。
- 输出日志保存 `tmp/memory-tests/`；总结保存 `docs/MEMORY_TEST_RESULTS.md`。不提交本地数据库或生成的向量索引。

|---|---|---|
| M01 | 未达预算的 12～19 条短历史 | 全部原文按角色保留，不因超过 8 条就压缩；摘要模型调用为 0 |
| M02 | 构造 20 条达到测试预算，再增长到 32 条 | 首次移出 1～12，保留 13～20；中间继续增长；第二次只处理 13～24，不重复摘要 |

## 执行顺序与命令

使用项目可用 Python，先记录版本与解释器路径。设置进程级测试默认环境，不修改 `.env`：

```powershell
$env:MODEL_PROVIDER='mock'
$env:RAG_EMBEDDING_PROVIDER='hash'
$env:RAG_RERANKER_ENABLED='false'
```

1. 静态检查：`git diff --check`，`python -m compileall -q app tests`。
2. 新 Memory 测试：`python -m pytest tests/test_memory_upgrade.py -q`。按矩阵逐项修复，不跳过失败用例。
3. Memory 与调用链：`python -m pytest tests/test_memory.py tests/test_agent_harness.py tests/test_agent_runtime.py tests/test_tool_queue_and_mcp.py -q`。
4. 完整回归：`python -m pytest -q`。
5. 独立工程验证：`python -m app.harness.runner --json`，必要时先确认其配置只使用临时数据库与索引。

所有命令的退出码、通过/失败数、执行时间和失败修复记录写入结果文档。日志输出过长时保留日志文件，终端只展示摘要。

## 通过标准与限制

- 自动测试和工程验证无未解释失败；所有实际执行的测试数量与状态如实记录。
- 事务、边界、身份隔离、更正、重试和预算的关键路径有可重复自动断言。
- mock/hash 测试验证工程正确性，不代表真实模型的语义提取质量或真实 embedding 的召回率。
- 真实模型盲审、FastEmbed 模型效果、在线 Redis 和 MySQL 并发属于需独立环境的后续验收；没有实际执行就标记未验证，不用 SQLite 结果替代。
- 如果无法运行某项，记录阻塞原因与已完成替代检查，不声称该项通过。
