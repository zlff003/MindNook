# 长对话记忆可靠性修复结果

报告日期：2026-10-20。真实 API 测试执行于 2026-10-19 至 20 日。

## 结论

本轮完成代码修改、隔离环境回归和真实模型复测。记忆链路改为“保留原话证据 → 持久保存事实 → 按事实生成摘要”，更正必须逐条审核，失败会留下可追踪的任务。

全量自动化测试 159 项通过。真实模型第二轮 60 轮测试的 10 个问答检查，人工逐项判断为 9 个完整通过、1 个部分通过；修复沟通偏好召回后，在该轮数据库副本上追加的 4 个检查全部通过。仍有 3 条更正任务未通过独立审核，不能据此宣称长对话记忆已经完全可靠。

## 改了什么

1. **事实必须有原话依据。** 模型只从指定的小批消息提取原文，服务核对消息归属、原话和完整句子，防止把当前话题写入旧消息、截掉否定词或把建议当成已做过。
2. **摘要不再承担唯一存储职责。** 事实单独保存在 SQL；摘要是有字数限制的确定性投影。摘要放不下的事实仍然存在，提取进度与摘要进度分开维护。
3. **更正只影响明确目标。** 模型选择目标后，再由独立模型请求审核；服务控制更新动作、来源和版本。只批准部分目标时记为 partial，避免把同一句中无关的有效事实一起撤回。
4. **后台任务可恢复。** 批次保存状态、次数、租约和错误。失败不推进提取进度，支持重试与缩小批次；后续普通聊天不会抹掉尚未处理的更正。默认前台不调用记忆模型。
5. **补充原文和偏好召回。** 查询“最早”时优先早期证据，原文回退携带后续更正；长期沟通偏好有独立预算，临时要求不自动当成长期偏好。
6. **旧数据可审计、可重建。** 无原话证据的旧记忆和旧摘要存档并安排重新提取。重建脚本先创建数据库副本，在副本运行，不自动切换业务数据库。

## 真实模型测试

模型为配置中的 Bailian `qwen-plus`。两次完整运行各写入 60 条模拟用户消息和 60 条固定助手回复；模型 API 用于事实提取、更正目标选择、独立审核和问答检查。**不是让模型自由生成 60 轮双方聊天。**

运行使用独立 SQLite 和向量索引，经过实际持久任务队列及 InlineToolDispatcher；测试将空闲等待设为 0。ThreadedToolDispatcher 另在自动化测试中验证，未用线上时间间隔完成整轮真实 API 压测。

## 使用边界

- 本轮没有在业务数据库执行迁移、重建或自动切换，也没有重启线上服务。旧数据迁移会随部署后的应用启动流程执行；需要预先保留业务备份。
- 重建脚本的副本准备流程已经测试，未针对业务库运行付费的完整重建。
- 原话校验保证引用能追溯，不能证明模型对归属、类别、语义的判断绝对正确；独立审核仍可能误判或拒绝合理更正。
- 原文回退是有上限的词项检索，可能漏掉同义表达或候选范围之外的记录。摘要不能代替全部历史。
- 这是单组构造长对话的复测，没有覆盖所有真实用户表达；未做真实 MySQL/Redis 多实例并发验证。不能把本次结果当成通用准确率承诺。
