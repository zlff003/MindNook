# MindNook 持久化分层记忆

> 版本：4.0；更新日期：2026-10-19。
> 设计依据：[MEMORY_UPGRADE_PLAN.md](./MEMORY_UPGRADE_PLAN.md)。测试先行方案：[MEMORY_TEST_PLAN.md](./MEMORY_TEST_PLAN.md)；执行结果：[MEMORY_TEST_RESULTS.md](./MEMORY_TEST_RESULTS.md)。
> 本轮可靠性修复：[测试方案](./MEMORY_RELIABILITY_TEST_PLAN.md)、[结果与变更文件](./MEMORY_RELIABILITY_RESULTS.md)。

## 运行流程

`AgentHarness` 校验会话和请求幂等，领取数据库会话租约，保存当前学生消息为 `generating`。`MemoryService.prepare_turn()` 读取近期原文、事实摘要、相关事实、稳定偏好和历史原文。默认前台不调用记忆模型，更正和超预算历史进入持久化后台队列；当前输入不混入历史。`MEMORY_FOREGROUND_MODEL_CALLS=true` 仅用于需要同步处理的诊断/兼容场景。

Runtime 消费已经组装的 `MemoryContext`，完成理解、风险评估、知识/Skills 加载、生成、审查与修复。Harness 在提交回复前再次验证租约，原子保存消息、Trace 与闲置提取任务，提交后刷新 Redis 并唤醒任务队列。

## 三层内容

| 层 | 数据源 | 规则 |
|---|---|---|
| 最近原文 | `chat_messages`，Redis v2 尾部缓存 | 未达预算可超过 8 条；压缩成功后默认保留 8 条，继续积累 |
| 当前摘要 | `conversation_summaries` | 从已保存事实确定性选取，最多 400 字；每项关联具体 memory_id |
| 长期记忆 | `user_memories`，独立 Chroma 集合 | 默认召回最多 3 条相关事实，另有独立预算的偏好和原文回退 |

Agent 私有记忆继续按 Agent/会话隔离；Trace 仅用于审计，不回流到学生记忆。

## 压缩与事务

- SQL 查询以当前快照上界和 `summarized_until_message_id` 为准，不能跨过尚未结束的旧消息。
- Redis 默认缓存 40 条，但必须核对 SQL 消息 ID 集合；缓存不能决定哪些消息已经被摘要。
- 大量历史按页读取，默认每批最多 8 条消息、每次后台处理最多 3 批。
- 提取模型仅接收当前批次消息，返回来源 ID、完整句子原文、归属/阶段/类型及已检查消息列表。不能看到当前 focus，也不能更新/撤回已有事实。程序验证原文、归属用户、句子边界和完整批次覆盖；按句号/分号进一步拆分，逗号不拆，避免切掉否定。
- 事实、事件、提取游标、摘要投影、批次状态与索引任务共享事务；写入失败全部回滚。模型不持有数据库写事务。提取游标独立推进，绝不使用两个游标的最大值跳过消息。
- 模型漏掉旧事实不会删除旧事实；摘要装不下的事实仍留在 SQL。摘要不再依赖全量旧证据覆盖校验。
- `memory_batches` 保存稳定批次键、范围、次数、状态及失败原因。前台遵循冷却时间；后台可拆小失败批次重试。默认最多 3 次，耗尽后原文仍可检索，不能假报完成。
- 摘要或批次处理失败时，仅裁减本轮上下文，不虚构成功边界；Trace 标注 `background_incomplete`，安排持久化重试。
- 单条原文超过单批可处理预算时不截断后伪称处理完成；保持边界并降级。需调整模型上下文/批次配置才能消化该类极端输入。

## 更正、反馈与短会话

明确更正/效果反馈的线索触发核对。模型只能提议目标 ID、预期版本和 correction/evolution 关系，证据和更新正文由程序绑定为当前用户原话。第二次独立模型调用审核每个目标，只提交通过审核的目标；全部不通过则不改事实。部分通过记为 partial，剩余目标保留待核对状态并重试，不能假报整批完成。模型没有直接删除事实的权限。

`memory_events` 保存目标事实的前后版本、原话和关系。更正只失效目标事实的旧证据，不全局失效消息；同一句的其他事实、新更正证据仍可使用。超时/歧义不会批量把候选事实改成 disputed。待核对原话按时间注入上下文，提醒回复遵从更正并确认歧义。

跨会话更正按 memory_id 移除其他摘要的旧投影；旧版无 ID 的摘要采用精确正文匹配并在迁移时重建。普通新消息不取消已排队的更正；旧更正不能覆盖来源更晚的事实。

短会话闲置提取默认等待 300 秒，明确反馈可立即安排；历史达到预算 75% 时提前排队。旧闲置任务遇到新消息可跳过，但更正任务不会被普通聊天取消。首次进入另一会话会安排上一会话的补提取，同时允许从原始历史取证。

## 召回与索引

检索内容来自当前输入和最近 4 条对话，保留角色帮助解释指代。Chroma 查询首先过滤 `student_id`；按结果 ID 回 SQL 再验证身份、有效状态与版本。默认召回 8 个候选，筛选最多 3 个；无关结果可为空。

与近期完整原文或摘要完整重复的结果不重复注入；摘要只覆盖同来源的一部分时不直接删除整条记忆。历史记录带时间、来源和有效状态，不能覆盖系统规则或直接决定当前危险。

偏好预算默认 400，原文回退 1600，待核对更正 800，均从总上下文额度预留。原文回退按用户过滤，词项候选同时取历史两端；“最初/最早”优先最早匹配原文。旧原文携带后续相关更正，装不下完整组合时宁可省略，不孤立呈现旧错误。词项检索仍可能漏召回；没有检索到不等于用户没有说过。

索引同步独立重试；召回时旧向量仅提供 ID，正文取 SQL 并重新检查相关性。尚未同步的少量 SQL 记录可通过当前正文评分补充召回。索引集合名包含 embedding 配置签名；更换 embedding 后旧签名记录可进入 SQL 补充候选。大规模重建仍应通过后台重放索引任务进行。

## 预算与成本

- `context_budget.py` 统一检查所有 Runtime 模型调用和摘要调用；包含系统规则、私有记忆、摘要、长期记忆、原文、当前输入、知识与 Skills。
- 默认上下文 16384、回复预留 1024、余量 512；可用 `MODEL_CONTEXT_LIMITS` JSON 为不同模型设置容量与输出上限。
- 当前使用 UTF-8 字节数的保守估算，**不是精确 tokenizer**；真实用量优先使用服务端 usage。
- 回复 Prompt 超预算时先移除可选知识和私有记录，必要规则、关键 Skills 与当前输入保留；仍超预算则走现有安全回退。
- OpenAI-compatible 请求设置 `max_tokens`，流式 usage 不再丢弃。缺失 usage 时标记为估算。
- 每次记忆模型调用以 `MEMORY_CALL` 记录保存状态和用量；模型已返回但结构校验失败时仍保存已发生费用。后台任务结果中的 calls 只是引用性汇总，统计时不要与 `MEMORY_CALL` 再累加。
- `AgentRun.model_calls` 仍是 Runtime 调用数；完整成本为 Runtime 用量加独立 `MEMORY_CALL` 记录，避免把摘要成本遗漏。

## 后台任务与兼容性

复用持久化 `ToolJob`：`MEMORY_EXTRACT`、`MEMORY_COMPACT`、`MEMORY_RECONCILE`、`MEMORY_INDEX_SYNC`；独立记忆线程池不会占用个案/预警线程。任务领取用状态条件更新保证 SQLite 下互斥；启动只恢复过期任务，保留其他 worker 的有效租约。

应用启动创建事实事件表 `memory_events` 与批次表 `memory_batches`，并保留已有的幂等迁移。旧版没有原文证据的记忆先完整存档、标为 `legacy_unverified`，旧摘要存档并重置游标，排队从原始聊天重建；不修改聊天原文和风险/报告表。

可先运行 `python scripts/memory_rebuild.py --source <SQLite文件> --output <新目录>` 制作影子重建库。默认不调用模型，源库只读，保存完整 `source_snapshot.db`。加 `--live --max-calls N` 才提取副本消息并重建独立索引；不会自动切换业务库。此脚本针对 SQLite；MySQL 部署应先在备份/测试实例验证迁移。

| 文件 | 职责 |
|---|---|
| `memory/service.py` | 前台读取、更新编排、后台任务业务 |

| `memory/history.py` | 原始消息回退、后续更正组合、偏好注入 |
| `memory/index.py`、`retrieval.py` | 独立向量集合、身份过滤、SQL 回查、去重 |
| `memory/cache.py`、`store.py` | Redis 热缓存与旧策略兼容 |
| `services/context_budget.py` | 统一预算检查 |
| `memory/schema.py` | 旧库兼容迁移 |

真实模型提取准确性、FastEmbed 召回效果、在线 Redis 和 MySQL 并发需要独立环境验收；离线工程测试结果不代替这些验证。
